ERP MCP 能力清单（用于 Skill 编写）
整理日期：2026-07-14
MCP 名称：erp
MCP 地址：https://portal.fangline.cn/mcp

重要说明：
1. 本文基于当前 Codex 会话中实际暴露的 erp MCP 工具 schema、工具说明，以及已调用返回样例整理。
2. 当前 erp MCP 主要是“查询类”工具，没有看到写入、修改、删除 ERP 数据的工具。
3. 统计接口 queryRptData 与明细接口 queryContractFinanceData 不是天然一一对应。写 Skill 时不要默认“统计数 = 明细条数”，必须做口径说明。
4. queryRptData 的 startDate/endDate 只在工具 schema 中说明为“开始日期/结束日期”，没有明确底层对应签约日期、结单日期、实收日期、审核日期或业绩分配日期。
5. queryContractFinanceData 的工具说明中写明了不同 type 的日期口径，但入参名称仍是 paymentDateBegin/paymentDateEnd 或 settlementDateBegin/settlementDateEnd，实际使用时要在 Skill 中提示口径风险。


============================================================
一、当前可用工具总览
============================================================

当前已暴露的 erp MCP 工具：

1. queryRptData
   类型：统计指标查询
   用途：查询房源、客源、带看、合同、访问、通话、分享、考勤、面访陪访等统计指标。

2. queryContractFinanceData
   类型：合同/财务/业绩/付款明细查询
   用途：查询实收明细、应收应付、业绩分配、合同明细、付款明细。

3. listHouseByCondition
   类型：房源列表查询
   用途：按租售业务、区域、商圈、小区、价格、面积、户型、装修、楼层、电梯等条件查询在售/在租房源。

4. getHouseByHouseNo
   类型：房源详情查询
   用途：根据房源编号查询单套房源完整信息，包括基本信息、挂牌信息、图片等。

5. getSectionMarketBaseInfo
   类型：小区基础信息查询
   用途：查询小区名称、区域、板块、经纬度等基础信息。

6. getSectionMarketData
   类型：小区行情综合数据查询
   用途：查询小区成交均价、成交量、成交周期、看房量、价格趋势、挂牌均价、流动性、竞争力等。

7. listHotSection
   类型：热门小区榜单查询
   用途：查询成交量、带看量、浏览、挂牌、分享等热门小区排行榜。


============================================================
二、queryRptData：统计指标查询
============================================================

工具名：
queryRptData

工具说明：
【行程统计】查询房客源合同等统计指标数据。

适合用途：
1. 做经营统计看板。
2. 按部门/人员统计某个指标。
3. 查合同成交单量、合同应收、合同实收、分边量。
4. 查新增房源、新增客源、带看、跟进、分享、访问、通话、考勤等指标。
5. 做“某部门某时间段某指标排名”。

不适合用途：
1. 直接查具体合同号。
2. 直接查明细字段。
3. 直接解释统计指标底层 SQL。
4. 直接判断 startDate/endDate 是签约日期还是结单日期。


------------------------------------------------------------
2.1 入参 schema
------------------------------------------------------------

query: object

query.bizType
类型：string
必填：是
可选值：
- 买卖
- 租赁
- 新房
- 全部

说明：
业务类型。部分指标通过 bizType 区分二手房、租房、新房口径。

常见映射：
- 二手房合同/二手房业务：bizType = 买卖
- 租房合同/租赁业务：bizType = 租赁
- 新房合同/新房业务：bizType = 新房
- 全部业务：bizType = 全部


query.startDate
类型：string
格式：yyyy-MM-dd
必填：是
限制：日期范围不能超过 31 天

说明：
统计开始日期。

重要口径风险：
工具 schema 只说明“开始日期”，未明确该日期底层对应：
- 签约日期
- 结单日期
- 实收日期
- 审核日期
- 业绩分配日期
- 创建日期
- 其他 ERP 报表日期

写 Skill 时建议表述：
“queryRptData.startDate/endDate 是 ERP 行程统计口径的日期参数。当前 MCP 未公开其底层日期字段，不能直接等同于合同明细的签约日期或结单日期。”


query.endDate
类型：string
格式：yyyy-MM-dd
必填：是
限制：日期范围不能超过 31 天

说明：
统计结束日期。


query.indexName
类型：string
必填：是

说明：
指标名称。必须严格传工具支持的指标名，例如：
- 合同成交单量·份
- 合同应收·元
- 新增房源·套
- 二手房带看·组

注意：
指标名称中的“·”和单位必须准确，否则会返回“不支持的指标名”。


query.deptName
类型：string
必填：否

说明：
部门名称。不传则查询全部部门。

注意：
如果传入具体部门名，只能按 ERP 后台识别的部门名称匹配。


query.userName
类型：string
必填：否

说明：
人员名称。不传则查询全部人员。


------------------------------------------------------------
2.2 返回字段
------------------------------------------------------------

常见返回为数组，每一项类似：

deptName
类型：string
含义：部门名称

userName
类型：string
含义：人员名称

indexValue
类型：number
含义：该部门/人员在该指标下的统计值

返回示例：
[
  {
    "deptName": "示例部门",
    "userName": "示例人员",
    "indexValue": 7
  }
]

------------------------------------------------------------
2.5 queryRptData 写 Skill 注意事项
------------------------------------------------------------

1. 日期范围必须拆分：
   如果用户选择多个月，Skill 应按每月或每 31 天拆分多次调用，然后合并结果。

2. 指标名必须精确：
   “合同成交单量·份”不能写成“合同量”“成交单量”“合同成交单量”。

3. 统计值不是明细：
   queryRptData 返回的是汇总行，不返回合同编号、房源编号、客户、业主等明细。

4. 合同成交单量与合同明细可能不一致：
   例如 2026-07 新房：
   - queryRptData 统计值：7
   - queryContractFinanceData(type=合同明细) 查到新房合同明细：8
   - queryContractFinanceData(type=业绩分配) 匹配新房合同：7
   说明“合同成交单量·份”可能更接近 ERP 统计/业绩分配口径，而不是合同明细简单条数。

5. 不要编造定义：
   如果用户问 startDate 到底是签约日期还是结单日期，当前 MCP 信息不足以确认，应回答“未公开底层日期字段”。

三、queryContractFinanceData：合同/财务/业绩/付款明细查询
============================================================

工具名：
queryContractFinanceData

工具说明：
查询合同实收明细、应收应付、业绩分配、合同明细、付款明细。

通过 type 参数区分数据类型：
- 实收明细
- 应收应付
- 业绩分配
- 合同明细
- 付款明细


------------------------------------------------------------

------------------------------------------------------------

type
类型：string
必填：是
可选值：
- 实收明细
- 应收应付
- 业绩分配
- 合同明细
- 付款明细

paymentDateBegin
类型：string

类型：string

settlementDateEnd
类型：string
格式：yyyy-MM-dd
必填：与 paymentDateEnd 二选一
说明：结单日期结束。

限制：
1. 支付日期和结单日期其中一组必填。

3.8 queryContractFinanceData 写 Skill 注意事项
------------------------------------------------------------

1. 该工具能查明细，比 queryRptData 更适合回答“具体是哪几份合同”。

2. 如果用户问合同成交单量，应该先用 queryRptData 查统计，再用 queryContractFinanceData 查合同明细/业绩分配进行核对。

3. 明细条数可能与统计数不同：
   - 合同明细可能包含未进入统计的合同。
   - 业绩分配可能更接近统计口径。
   - 实收明细按支付日期，会包含签约日期不在本月但本月收款的合同。

4. 不要把 status=0/1 直接解释成“未审核/已审核”，除非 ERP 文档明确。

5. 合同明细中可能包含敏感信息：
   - 业主姓名
   - 客户姓名
   - 证件号
   - 地址
   写 Skill 时应加入隐私保护规则，默认脱敏证件号、手机号等敏感字段。

十一、写 Skill 的建议结构
============================================================

建议 Skill 分为以下模块：

1. 统计查询模块
   使用 queryRptData。
   适合回答：
   - 某月合同成交多少份？
   - 某部门带看多少组？
   - 某人新增房源多少套？
   - 某业务线合同实收多少元？

2. 合同明细模块
   使用 queryContractFinanceData。
   适合回答：
   - 具体是哪几份合同？
   - 合同号是什么？
   - 签约日期是什么？
   - 成交人是谁？
   - 合同状态如何？
   - 应收/实收/业绩分配如何？

3. 房源查询模块
   使用 listHouseByCondition + getHouseByHouseNo。
   适合回答：
   - 有哪些在售/在租房源？
   - 某小区有哪些房源？
   - 满足预算和户型的房源有哪些？
   - 某房源详情是什么？

4. 小区行情模块
   使用 getSectionMarketBaseInfo + getSectionMarketData + listHotSection。
   适合回答：
   - 某小区行情如何？
   - 成交均价走势如何？
   - 哪些小区成交量高？
   - 某区域热门小区有哪些？


============================================================
十二、Skill 中必须写清楚的口径规则
============================================================

建议写入 Skill 的强制规则：

1. 当用户问“统计值”时，优先使用 queryRptData。

2. 当用户问“具体明细/具体是哪几份”时，必须使用 queryContractFinanceData。

3. 当用户问“合同成交单量·份具体有哪些合同”时：
   - 先用 queryRptData 查统计值。
   - 再用 queryContractFinanceData(type=合同明细) 查合同明细。
   - 再用 queryContractFinanceData(type=业绩分配) 核对是否更接近统计值。
   - 如果三者不一致，必须明确说明“不一致”，不能强行解释成一致。

4. 当用户问 startDate/endDate 的日期口径时：
   - 不能说“就是签约日期”。
   - 应说明：queryRptData 未公开底层日期字段。
   - 可以说：queryContractFinanceData 的合同明细/业绩分配工具说明为按签约日期筛选。

5. 当日期跨度超过 31 天时：
   - 自动拆分为多次调用。
   - 按月份或 31 天窗口合并。

6. 当涉及个人证件号、业主姓名、客户姓名、详细地址时：
   - 默认脱敏。
   - 除非用户明确需要完整字段并且场景合理。

7. 当用户要求导出报表：
   - 先说明字段来源。
   - 标明统计口径。
   - 标明查询时间范围。
   - 标明是否有口径不一致。

当统计值与明细不一致时，必须向用户展示差异并说明可能属于统计归属口径差异。”
