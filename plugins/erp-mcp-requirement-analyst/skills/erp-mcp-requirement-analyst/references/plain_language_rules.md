# 客户侧通俗表达规范

客户通常不懂接口名、字段名和技术术语。主界面必须先说明业务含义，技术细节只能放在折叠区。

## 主界面不要直接出现

- queryRptData
- listHouseByCondition
- queryContractFinanceData
- isNew
- unitPrice
- bizType
- schema
- JSON
- lineage
- drilldown
- 算术平均
- 面积加权
- 日期口径
- 时间口径
- MCP 支持但口径需说明

这些内容只能放进折叠的 `数据来源与技术说明`。

## 推荐说法

| 技术说法 | 客户能听懂的说法 |
|---|---|
| MCP 直接支持 | 系统可以直接查 |
| MCP 支持但口径需说明 | 系统能查，但统计方式需要说明 |
| MCP 不支持 | 系统目前查不到 |
| 需导出 | 需要补充一张系统表格 |
| queryRptData 月度统计 | 系统报表里的月度统计 |
| isNew=是 | 现在仍被系统标记为“新上” |
| unitPrice | 每平方米挂牌价 |
| 算术平均 | 每套房同等权重计算平均价 |
| 面积加权平均 | 按房源面积计算整体均价 |
| 日期口径 / 时间口径 | 这个数字按哪个日期统计 |
| 组织维度 | 按全公司、片区、门店或个人查看 |
| drilldown | 查看这个数字对应的明细 |
| lineage | 这个数字是怎么算出来的 |

## 先给结论，再给解释

错误说法：

> 日期口径：上月新上房源数量使用 ERP queryRptData 官方统计日期；挂牌均单价使用当前 MCP 新上标签 isNew=是，非严格本月新上日期。

正确说法：

> 新上房源数量可以按你选择的月份统计。挂牌均价目前只能根据现在仍被系统标记为“新上”的房源计算，所以这个均价是当前参考价，不一定完全等于所选月份新录入房源的均价。

然后在折叠区补充接口和字段。

## 不要把内部说明做成下拉框

如果系统只有一种可行方式，不要让客户选择。

错误：

> 数量=上月(2026-06);均价=本月(2026-07)

正确：

> 本次数据如何统计：新上房源数量按统计月份计算；挂牌均价按当前仍标记为“新上”的房源计算。

## 选项卡写法

每个选项最多包含：

- 一句标题；
- 一到两句普通中文解释；
- 一个短状态标签：
  - 可以直接查；
  - 能查，但要说明统计方式；
  - 需要补充合同表；
  - 需要补充人员表；
  - 系统目前做不到。

不要在同一个选项上重复显示多个“需导出”标签。
