# 用户侧通俗表达规范

客户通常不懂接口名、字段名和技术术语。主界面必须先说业务含义。

## 一、主界面禁止直接堆技术词

以下内容不作为标题、选项主文案或核心说明：

- queryRptData；
- listHouseByCondition；
- queryContractFinanceData；
- isNew；
- unitPrice；
- bizType；
- schema；
- JSON lineage；
- 算术平均；
- 面积加权；
- 日期口径；
- 口径需说明；
- MCP 直接支持；
- MCP 支持但口径需说明。

技术名只能放进折叠的“数据来源与技术说明”。

## 二、推荐说法

| 技术说法 | 客户能听懂的说法 |
|---|---|
| MCP 直接支持 | 系统可以直接查 |
| MCP 支持但口径需说明 | 系统能查，但统计方式需要说明 |
| MCP 不支持 | 系统目前查不到 |
| 需导出 | 需要补充一张系统表格 |
| queryRptData 月度统计 | ERP 系统的月度统计 |
| isNew=是 | 系统当前标记为“新上” |
| unitPrice | 每平方米挂牌价 |
| 算术平均 | 把每套房的单价相加，再除以房源套数 |
| 面积加权平均 | 把所有房源总价相加，再除以总面积 |
| 日期口径 | 这项数据是按哪个日期统计 |
| 组织维度 | 按全公司、片区、门店或个人查看 |
| drilldown | 查看这个数字对应的明细 |
| lineage | 这个数字是怎么计算出来的 |

## 三、说明必须先给结论

错误：

> 日期口径：上月新上房源数量使用 ERP queryRptData 官方统计日期；挂牌均单价使用当前 MCP 新上标签 isNew=是，非严格本月新上日期。

正确：

> 上月新增房源的总套数可以按月份准确统计。挂牌均价目前只能根据“现在仍被系统标记为新上”的房源计算，因此这个均价是当前参考值，不一定完全等于上月新录入房源的均价。

然后在折叠区补充技术信息。

## 四、选项卡写法

每个选项最多包含：

- 一句标题；
- 一到两句普通中文解释；
- 一个简短状态标签：
  - 可以直接查；
  - 能查，但要注意统计方式；
  - 需要补充合同表；
  - 需要补充人员表；
  - 系统目前做不到。

不得在同一选项上重复显示两个“需导出”标签。
