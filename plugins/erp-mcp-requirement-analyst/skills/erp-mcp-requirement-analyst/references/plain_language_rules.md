# 客户侧通俗表达规范

客户通常不懂接口名、字段名和技术术语。主界面必须先说明业务含义，技术细节只能放在折叠区。

## 主界面不要直接出现

- queryRptData
- listHouseByCondition
- queryContractFinanceData
- isNew
- unitPrice
- bizType
- schema
- JSON
- lineage
- drilldown
- 算术平均
- 面积加权
- 日期口径
- 时间口径
- MCP 支持但口径需说明

这些内容只能放进折叠的 `数据来源与技术说明`。

## 专业词后面必须加括号解释

如果业务上必须使用稍微专业的词，第一次出现时必须写成：

> 术语（短解释）

括号里的解释要短，客户扫一眼就能懂。更长的解释放到下一行或说明卡里。

| 可以保留的词 | 推荐写法 |
|---|---|
| 挂牌均价 | 挂牌均价（当前挂牌单价的平均值） |
| 两种都展示 | 两种都展示（同时给出两套算法结果，方便对比） |
| 每套等权 | 按套数简单平均（每套房都算一票，小房子和大房子影响一样，适合快速粗略核对） |
| 每套房等权均价 | 按套数简单平均（每套房都算一票，小房子和大房子影响一样，适合快速粗略核对） |
| 面积加权 | 按面积计算均价（先算每套房单价，再按面积大小综合；大面积房源影响更大，适合看市场均价） |
| 按面积加权均价 | 按面积计算均价（先算每套房单价，再按面积大小综合；大面积房源影响更大，适合看市场均价） |
| 新上房源 | 新上房源（系统标记为最近新增的房源） |
| 层级筛选 | 层级筛选（按全公司、片区、门店等范围筛选） |
| 明细 | 明细（组成这个数字的具体记录） |
| 分母 | 分母（参与计算的总人数或总数量） |
| 去重 | 去重（同一条记录只算一次） |
| 数据来源 | 数据来源（这个数字从哪里查出来） |
| 统计方式 | 统计方式（这个数字按什么规则计算） |

不要只写：

- 两种都展示
- 每套等权
- 面积加权
- 每套房等权均价
- 按面积加权均价
- 层级筛选
- 明细

尤其是 WorkBuddy 原生选择卡里，选项标题也必须带括号解释。

## 推荐说法

| 技术说法 | 客户能听懂的说法 |
|---|---|
| MCP 直接支持 | 系统可以直接查 |
| MCP 支持但口径需说明 | 系统能查，但统计方式需要说明 |
| MCP 不支持 | 系统目前查不到 |
| 需导出 | 需要补充一张系统表格 |
| queryRptData 月度统计 | 系统报表里的月度统计 |
| isNew=是 | 现在仍被系统标记为“新上” |
| unitPrice | 每平方米挂牌价 |
| 算术平均 | 按套数简单平均（每套房都算一票，小房子和大房子影响一样，适合快速粗略核对） |
| 面积加权平均 | 按面积计算均价（先算每套房单价，再按面积大小综合；大面积房源影响更大，适合看市场均价） |
| 日期口径 / 时间口径 | 这个数字按哪个日期统计 |
| 组织维度 | 按全公司、片区、门店或个人查看 |
| drilldown | 查看这个数字对应的明细 |
| lineage | 这个数字是怎么算出来的 |

## 先给结论，再给解释

错误说法：

> 日期口径：上月新上房源数量使用 ERP queryRptData 官方统计日期；挂牌均单价使用当前 MCP 新上标签 isNew=是，非严格本月新上日期。

正确说法：

> 新上房源数量可以按你选择的月份统计。挂牌均价目前只能根据现在仍被系统标记为“新上”的房源计算，所以这个均价是当前参考价，不一定完全等于所选月份新录入房源的均价。

然后在折叠区补充接口和字段。

## 不要把内部说明做成下拉框

如果系统只有一种可行方式，不要让客户选择。

错误：

> 数量=上月(2026-06);均价=本月(2026-07)

正确：

> 本次数据如何统计：新上房源数量按统计月份计算；挂牌均价按当前仍标记为“新上”的房源计算。

## 选项卡写法

每个选项最多包含：

- 一句标题，标题里的专业词必须带括号解释；
- 一到两句普通中文解释；
- 一个短状态标签：
  - 可以直接查；
  - 能查，但要说明统计方式；
  - 需要补充合同表；
  - 需要补充人员表；
  - 系统目前做不到。

不要在同一个选项上重复显示多个“需导出”标签。

示例：

- `两种都展示（同时给出两套算法结果，方便对比）`
  同时显示“每套等权”和“按面积计算整体均价”两个结果，方便客户判断差异。
- `按套数简单平均（每套房都算一票，小房子和大房子影响一样，适合快速粗略核对）`
  把每套房的每平方米挂牌价相加，再除以房源套数。
- `按面积计算均价（先算每套房单价，再按面积大小综合；大面积房源影响更大，适合看市场均价）`
  先估算每套房总价，再用总价合计除以总面积合计。
- `按套数简单平均（每套房都算一票，小房子和大房子影响一样，适合快速粗略核对）`
  把每套房的每平方米挂牌价相加，再除以房源套数。
- `按面积计算均价（先算每套房单价，再按面积大小综合；大面积房源影响更大，适合看市场均价）`
  先估算每套房总价，再用总价合计除以总面积合计。

## 导出入口说法

如果最终页面可以导出本次结果，首轮或排版预览里要问：

> 最终页面是否需要导出表格？

选项写成：

- `需要导出本次结果`
  在最终页面放导出按钮，只导出本次已经查到并校验过的数据。
- `汇总和明细都导出`
  同时导出汇总数字和明细（组成这个数字的具体记录），方便后续核对。
- `暂时不需要`
  先看交互页面，后续需要时再补导出入口。

不要说“导出房源表”，系统支持导出的表格里没有房源表。
