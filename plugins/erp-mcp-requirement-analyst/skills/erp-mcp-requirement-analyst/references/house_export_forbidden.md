# 房源类查询：禁止建议导出房源表

这是最高优先级规则。

## 一、禁止事项

系统支持的导出表中没有独立房源表。Skill 在任何回答、HTML、导出建议、替代方案和错误提示中，都不得建议客户导出：

- 房源表；
- 新上房源表；
- 在售或在租房源表；
- 房源明细表；
- 带新上时间、录入时间或组织归属的房源表；
- 任何实质上属于房源数据导出的自创表名。

不得因为某个字段 MCP 查不到，就假设系统应该可以导出该表。

## 二、“上月新上房源”场景

现有能力可能出现两种不同数据：

1. ERP 的月份统计，可以给出某月新增房源总套数；
2. 当前房源列表中的“新上”标记，反映房源现在是否仍被系统标记为新上。

这两个结果不能混为一谈。

用户侧必须用普通中文说明：

> 上月新增房源的总套数可以按月份统计；但系统目前不能拉出一份“上月新录入房源的完整名单”。当前房源列表里的“新上”，只是房源现在仍处于新上状态，不一定全部是在上月录入。因此，用这些房源计算出来的均价只能作为当前新上房源的参考，不能当作严格的上月新上均价。

不得显示以下难懂主文案：

- `queryRptData`
- `listHouseByCondition`
- `isNew=是`
- `unitPrice`
- “日期口径未暴露”
- “MCP 支持但口径需说明”

这些技术内容只能放在折叠的“数据来源与技术说明”中。

## 三、字段不足时的合法方案

只能提供：

- 先查看 ERP 可以准确统计的月度数量；
- 再查看当前仍被标记为新上的房源及其当前均价；
- 将两组结果分开展示；
- 明确哪些是准确统计、哪些是参考值；
- 建议向产品顾问新增历史房源明细接口或房源新上日期字段。

绝对不能提供“导出房源表后再算”的方案。
