# 快速答案与按需明细规则

## 用户体验目标

客户最先需要的是一个可信数字，不是一张空白预览，也不是数字背后的几百条记录。

固定顺序：

1. 用 1-3 个问题确认会改变数字的定义；
2. 确认后立即执行最快的有效计算：优先现成汇总，没有时再用最少字段重新计算；
3. 在同一次结果中打开带数字的 MCP Apps Widget；
4. 页面筛选只重新查询汇总；
5. 点击蓝色数字才读取第一页明细；
6. 点击加载更多才读取下一页。

## 查询预算

### 定义确认前

- ERP 业务调用：0 次；
- 明细行：0 条；
- 大型参考文件：0 个；
- 只运行小型场景路由并显示必要问题。

### 定义确认后首次回答

- 有完全匹配的现成汇总：优先 1 次调用；
- 没有现成汇总：只调用计算公式真正需要的数据源和分页；
- 明细工具：0 次；
- 明细分页：0 页；
- 原始业务 JSON：0 个；
- 目标：数字完成后立即进入 Widget，不等待明细表和页面精装修。

重新计算时，“计算数据”与“展示明细”必须分开。即使计算需要扫描多页，也只保留公式需要的字段和累计值，不生成房源/合同详情表，不把原始行写入聊天。若预计超过 30 秒，先打开 Widget 显示 `正在计算核心数字`，计算完成后只更新指标卡。

### 页面换条件

- 每次点击只执行一个逻辑汇总任务；有现成指标时通常是 1 次调用，派生指标可包含必要的最小计算调用；
- 不得为了刷新数字调用明细工具；
- 快速连续点击时禁用查询按钮，避免重复请求。

### 点击数字

- 只有 `drilldown.available=true` 才显示蓝色链接；
- 第一次最多 20 条，绝对上限 50 条；
- 不得自动读取第二页；
- 用户点击加载更多后才读取下一页。

## 常见请求：上月新上房源数量

- 首轮若业务类型不明确，只问业务类型。
- 确认后通过 `showErpDashboard` 调一次 `queryRptData`。
- 使用现成指标 `新增房源·套`，不要用房源列表逐套计数。
- `queryRptData` 返回的部门和人员名称可作为小型筛选选项，但不要把这些汇总行展示成房源明细。
- 月度汇总没有同口径逐套房源时，数字不可显示为蓝色。
- 区域/商圈/小区筛选放在独立的 `当前新上房源` 视图；该视图先用 `size=1` 读取分页总数，点击数字后才读列表。

## 禁止行为

- 定义确认后先抓 200 套房源再计算数量；
- 为了“探测字段”读取样例房源；
- 汇总页面生成前分页读取房源或合同；
- 页面换部门时重新抓取全公司明细；
- 把当前新上列表总数说成上月新增；
- 用首屏返回的 1/20/100 条当总数；
- 在聊天里贴原始 JSON 或逐条数据进度。

## 客户可见进度

只使用简短中文：

- `请先确认业务类型，确认后马上给你汇总数字。`
- `核心数字已返回，你可以直接在页面里换条件。`
- `正在读取你点击的这一页明细。`

不要显示内部工具名、读文件、探测结构或英文进度。
