# 标准案例：查询上月新上房源数量和挂牌均价

用户需求：

> 查询上月新上房源数量，可以按层级筛选，并计算挂牌均价。

## 先拆成两个数字

### 月度新增房源数量

按客户选择的月份查询系统报表里的新增房源总套数。

客户侧说明：

> 这个数字表示该月份系统统计的新增房源总套数。

### 当前新上房源参考均价

当前房源接口只能查询现在仍被系统标记为“新上”的房源。

客户侧说明：

> 这个均价是根据现在仍被系统标记为“新上”的房源计算的。它可以反映当前新上房源的价格水平，但不一定完全等于上月新录入房源的均价。

## 绝不建议导出房源表

系统支持的导出表里没有房源表。

如果客户要求“严格计算上月新增房源的均价”，只能：

1. 说明现有接口不能取得上月新增房源的完整名单；
2. 提供当前能做到的参考结果；
3. 建议向产品顾问新增房源新上日期或历史明细接口；
4. 不得建议导出房源表。

## 首轮 HTML 的基础筛选

优先显示紧凑的基础筛选区：

- 统计月份：默认上月，可以切换月份；
- 查看范围：默认全公司；
- 业务类型：按实际可查询范围显示；
- 地理范围：区域、商圈、小区，只有真实可用时才显示；
- 组织范围：只在真实组织数据可用时显示。

不要把每个基础筛选都做成巨大选择卡。

## 均价计算说法

客户没有明确时，用普通中文提供：

- 每套房同等权重：把每套房的每平方米挂牌价相加，再除以套数；
- 按面积计算整体均价：把总价合计除以总面积合计。

默认推荐哪一种必须根据业务用途说明，不能只写“算术平均/面积加权”。

## 最终 HTML

顶部提供可用筛选，页面内容包括：

- 月度新增房源总套数；
- 当前新上房源套数；
- 当前新上房源参考均价；
- 为什么这两个数字不一定来自同一批房源；
- 按真实可用的地理或组织维度汇总；
- 可查看的房源明细；
- 技术信息折叠区；
- 当前接口限制和产品接口建议。

任何查询失败都显示“加载失败”或“暂无可验证数据”，不能显示假 0。
